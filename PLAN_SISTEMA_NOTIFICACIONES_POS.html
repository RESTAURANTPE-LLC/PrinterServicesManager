1. Resumen Ejecutivo

El sistema actual de pagos POS en QuipuNetX carece de un mecanismo robusto de notificaciones entre dispositivos. La comunicacion actual es fire-and-forget: si la notificacion HTTP al dispositivo origen falla, se pierde sin trazabilidad ni reintentos.

Este documento propone un Sistema de Notificaciones Bidireccional que:

  • Persiste cada notificacion con su payload, IPs, estado, reintentos y timestamps
  • Implementa reintentos automaticos con backoff exponencial
  • Permite consultar al POS el estado de transacciones pendientes
  • Ofrece un dashboard web de trazabilidad con estadisticas en tiempo real
  • Es reutilizable para cualquier tipo de transaccion (ordenpedido, delivery, venta)
  • Mantiene compatibilidad con Java (QuipuPos) via contratos REST/JSON estandar
  • Se integra en la BD SQLite existente sin nueva infraestructura
Principios aplicados: SRP (3 servicios separados), ISP (2 interfaces), OCP (tipos extensibles), DIP (inyeccion por interfaz). Compatible con .NET Framework 4.5.2.

3. Decision Arquitectonica: Base de Datos

✓ Decision: Usar la BD SQLite existente de QuipuNetX

CriterioBD ExistenteBD Nueva (descartada)
JOINs con transaccionordenpedido, ordenpedido, deviceclient Directo Imposible en SQLite
Migracion Auto (ALTER TABLE ADD COLUMN) Script manual
ORM (SugarRecord) Heredado directo Nueva conexion
Deployment Cero cambios Nuevo archivo .db
Sincronizacion Misma transaccion 2-phase commit

Justificacion: Las notificaciones necesitan correlacionarse con transaccionordenpedido, ordenpedido y deviceclient. En SQLite embedded, cross-DB JOINs no son viables. Una segunda BD solo agrega complejidad sin beneficio.

4. Modelo de Datos

4.1 Nueva Tabla: notificacion

CREATE TABLE IF NOT EXISTS notificacion (
    ID                      INTEGER PRIMARY KEY AUTOINCREMENT,
    NOTIFICACIONID          TEXT    NOT NULL UNIQUE,      -- UUID v4
    TIPNOTIFICACION         TEXT    NOT NULL,              -- "ordenpedido"|"delivery"|"venta"
    IDENTIFICADORASOCIADO   TEXT    NOT NULL,              -- UUID del registro asociado
    IPORIGEN                TEXT,                              -- IP dispositivo cliente
    IPDESTINO               TEXT,                              -- IP del POS destino
    NOMBREDISPOSITIVO       TEXT,                              -- Nombre del dispositivo origen
    TIPOPAGO                TEXT,                              -- "izipay"|"credibanco"|"niubiz"
    ESTADONOTIFICACION      TEXT    NOT NULL DEFAULT '1', -- 1=pendiente 2=completada 3=error 4=timeout
    FECHACREACION           TEXT    NOT NULL,
    FECHARESPUESTA          TEXT,                              -- Cuando respondio el destino
    CANTIDADREINTENTOS      INTEGER NOT NULL DEFAULT 0,
    PAYLOADENVIO            TEXT,                              -- JSON body enviado (para replay)
    MENSAJERESPUESTA        TEXT,                              -- Respuesta del POS
    VENTAID                 TEXT                               -- Venta generada si exitosa
);

4.2 Extension de transaccionordenpedido

-- SQLite-net auto-agrega columnas al detectar campos nuevos en la entidad:
ALTER TABLE transaccionordenpedido ADD COLUMN TRANSACCIONORDENPEDIDOID TEXT;  -- UUID unico
ALTER TABLE transaccionordenpedido ADD COLUMN NOTIFICACIONID TEXT;            -- FK a notificacion
ALTER TABLE transaccionordenpedido ADD COLUMN IPORIGEN TEXT;                 -- IP cliente origen
Migracion zero-downtime: SQLite-net agrega columnas automaticamente via ALTER TABLE ADD COLUMN al detectar el campo nuevo en la entidad C#. No requiere scripts de migracion manuales.

4.3 Refactorizar NotificarOrigenAsync

private static async Task NotificarOrigenAsync(string iporigen, JObject payload,
                                                  string notificacionId = null)
{
    // Agregar notificacion_id al payload para correlacion
    if (!string.IsNullOrEmpty(notificacionId))
        payload["notificacion_id"] = notificacionId;

    var client  = new RestClient("http://" + iporigen + ":8081");
    var request = new RestRequest("/api/rest/ordenpedido/response", Method.POST);
    request.AddParameter("application/json", payload.ToString(), ParameterType.RequestBody);

    var response = await client.ExecuteTaskAsync(request);
    // Si falla, el RetryService lo detectara automaticamente
}
